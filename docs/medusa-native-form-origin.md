# Medusa native form origin compatibility

At 4ec707765eca2c3e705754c4979762df16862f83, GitHub job 138406959860 reached the authenticated review form but failed waiting for MATCH. The aggregate verify job failed because browser verification failed; source verification passed. Native form submission uses a referrer-policy-dependent Origin header, and no-referrer can serialize it as null (see https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header). Both the review handler and the outer Worker set no-referrer while the handler requires an exact same-origin header. This is a supported causal hypothesis, not an observed POST header from the failed run. The change sets same-origin only on the Medusa route and retains exact origin checking, authentication, no-store, and cross-origin denial. The new regression asserts actual browser POST origin and status; unit tests additionally reject null and absent origins. Local browser reproduction was blocked by the execution environment's navigation policy. Fresh CI is required to verify the repair. No production deployment or hosted credentials changed.
